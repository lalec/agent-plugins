# Upgrade — Step 7 apply steps

> Paths of the form `../../shared/<file>` are relative to the upgrade skill's directory (`plugins/dev-workflow/skills/upgrade/`), i.e. the plugin's `shared/`. `<name>.md` for an entry point means `.claude/skills/<name>/SKILL.md` — see `../../shared/preflight.md § Where the entry points live`.

**A step that has been revised since it shipped needs a guard listing every clause, not the first one.** Each apply step ends with an idempotency condition. When a step is later extended — a new rule added to the same file sync — an install that took the earlier version already satisfies a guard written on the earlier phrase, so the extension silently never lands and the install reports current. Observed: one install took the gate lane on day one, the double-gate rule was added to that same step the next day, and its upgrade skipped the whole step while a second install (which had never taken it) got everything. **When you extend an apply step, extend its guard in the same edit** — and prefer listing the anchors over naming one, since re-running a text sync costs nothing and a missed clause costs a silent divergence.

Each step is idempotent — re-running the upgrade is safe.
